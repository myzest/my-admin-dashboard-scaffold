# 实施记录

## 已确认范围

普通服务器部署、一个初始管理员、MySQL 首版验收。管理员与普通用户共用登录和布局，后端按固定角色鉴权。

- 管理员创建、编辑、分页搜索和硬删除普通用户；注册开关保存到数据库，初始关闭。
- 普通用户登录个人面板，查看自己的四位小数余额和日志，修改自己的密码。
- 新用户余额 `0.0000`，单一余额单位，禁止负数和超过四位小数的输入。
- 管理员手动加减余额；用户行锁、余额更新与日志同事务、操作编号去重。
- 硬删除用户时，无论余额是否为零，删除账号、余额、全部日志及全部会话。
- 保留旧管理员账号密码及分类示例；新增迁移升级旧库，迁移规范写入两个主规范文件。

## 代码复核与修复（2026-10-21）

复核了页面、API、权限、金额事务、迁移和文档，修复以下问题：

- 调账响应丢失后，关闭弹窗会丢失操作编号，重开提交可能重复入账。现按管理员与用户保存待确认操作，先保存再请求；关闭或刷新后恢复原参数，成功确认或明确业务拒绝后才清理。存储读写失败时阻止新调账，清理失败时仍复用原编号确认。
- 注册失败时显式向 SWR 写入 `undefined`，导致表单卸载、已填内容丢失。现保留表单，仅在服务器确认关闭注册时重新读取开关。
- 工作台刷新清空缓存后，失败会退回最初的 SSR 余额。现只重新请求，失败时保留最近一次成功读取的余额并显示错误。
- 两个主规范文件区分非分页空数组与分页空 `items`，README 补充余额界面模块和调账恢复边界。

复核前快照及基线失败证据位于 `.local/review-before-2026-10-21/`。本轮 ESLint、Prettier、9 项单元测试、生产构建和 3 条 Chromium E2E 均通过。浏览器回归覆盖响应丢失后关闭重开、刷新、恢复记录写入及清理失败、相同编号多次提交只记一笔、注册失败保留字段及注册关闭、余额刷新失败保留最新数据。后端与迁移未改动，沿用上方的 MySQL 与迁移验收记录。

复测数据已清理，注册开关恢复关闭，服务已重启清空测试限流。与升级前 SQL 备份逐项核对，原管理员编号、用户名和密码哈希均未改变；客户端构建产物未发现本地凭据。复核结果另存于上述目录的 `verification.json`。

恢复记录使用当前标签页的 `sessionStorage`，不承诺关闭标签页、清除浏览器数据或换设备后的自动恢复；这时先核对余额日志。未引入持久任务队列或新接口。

复杂度建议：`src/modules/settings/SettingsPage.jsx:23` 对访客注册配置的缓存同步只写入管理员自己的 SWR 缓存，退出后缓存会重建，可删除这处调用及对应 Hook，净减 2 行。本轮仅记录这项非功能建议。

## 当前实现边界

- 会话有效期 12 小时，数据库保存会话记录；退出后撤销对应记录。Cookie 使用 `HttpOnly`、`SameSite=Lax` 和显式的 `secure: false`。
- 双角色升级将 Cookie 名由 `admin_session` 改为 `starter_session`，旧浏览器需重新登录；账号密码不变。修改密码撤销全部会话。
- 登录限流为每个 socket IP、每个进程 15 分钟内最多 10 次尝试；不信任客户端传入的 `X-Forwarded-For`。反向代理后访问可能共享代理 IP 的配额，多实例共享限流需后续另行设计。
- 公开注册独立使用相同的限流额度；关闭注册与注册事务通过设置行锁确定提交顺序。管理员创建用户不受注册开关影响。
- 管理员初始化不提供默认密码，重复运行不会重置已有管理员。修改环境变量中的初始密码不会修改数据库中的密码。
- MySQL 迁移包含自动提交的 DDL。发布前备份数据库，并由单个部署进程执行迁移。
- 当前 React 19 + Arco 组合通过公开的 `Message.useMessage()` 显示提示，弹窗使用受控组件；不依赖 Arco 的私有兼容补丁或全局样式覆盖。
