## Web 与 Worker 统一启动（2026-10-25）

- `npm run dev` / `npm run start` 由同一 JavaScript 入口管理 Next.js 与 BullMQ Worker，保留两个独立进程；MySQL、Redis 继续独立运行。统一入口先按命令设置 development / production，再加载配置。迁移、初始化和生产构建仍由单独命令执行。
- Web 通过现有 `/health` 和本次启动标记确认可访问，Worker 在完成数据库连接、Redis 连接与调度注册后发送就绪通知；两者均就绪才输出 `application-ready` 并通知 PM2。公开健康检查 JSON 保持不变，受控探测才返回启动标记响应头。
- 任一服务启动失败或运行中被管理的服务进程意外退出，停止另一方并整体非零退出；单个任务失败及 Redis 运行中短暂断线沿用已有策略。正常停止允许 Worker 最多 30 秒收尾，统一入口在 31 秒后强制清理仍存活的子进程组。
- 增加单实例 `fork` 的 PM2 配置，启用就绪通知、35 秒停止窗口与 5 秒重启间隔。删除重复的 npm 启动前钩子和 `check-env.js`，未增加依赖；独立 Worker 命令继续保留供排障或有计划的扩容。
- 环境文件解析复用现有 `@next/env` 和 `dotenv`，没有自行解析 `.env`。Web 与 Worker 继承相同环境，模式、变量优先级和字面 `$` 均有回归覆盖。
- 子进程停止失败会向统一入口传递非零退出状态；兼容 Next.js 正常响应 `SIGTERM` 时返回 143。进程组清理覆盖开发 CLI 的后代进程，也兼容 macOS 对尚未回收进程组返回 `EPERM` 的情况。
- 使用步骤与部署验收见 [统一启动与宝塔部署](application-startup.md)。

### 统一启动复核

- PM2 默认向整个进程树发送 `SIGINT`，导致 Worker 同时收到 PM2 的 `SIGINT` 与统一入口的 `SIGTERM`，并把 Next.js 的正常退出码 130 误报为失败。配置显式设置 `treekill: false` 后，由统一入口独自负责子进程停止；同步修正宝塔部署说明。
- 首个服务异常退出后，如果另一进程停止超时，原逻辑会保留首个错误却漏掉 `APPLICATION_STOP_TIMEOUT`。现在同一条错误保留初始原因和强制清理信息，并增加真实子进程回归。
- 开发启动测试原先先注册删除构建目录、再注册停止应用的收尾钩子，失败路径可能在进程退出前删除文件。构建目录清理移到父测试，确保子测试的应用停止钩子先执行。

复杂度复核未发现需要删除的多余依赖或抽象。修复后通过 50 项单元测试、ESLint、Prettier 和差异空白检查；另以隔离 PM2 7.1.1、真实统一入口和模拟 Next.js 退出码／Worker 收尾的服务替身进行验证：默认配置停止时退出码为 1，修复后退出码为 0，Worker 只收到一次 `SIGTERM`，没有停止错误。真实 Next.js、MySQL、Redis 的启动与队列测试沿用上方实施阶段记录，本轮未重复运行。

### 后台任务复核与修复

- 原生产者只重连两次，Redis 恢复后仍报 `Connection is closed`。现使用 BullMQ 默认持续重连，投递仍快速失败；命令和 Worker 的首次连接检查增加 10 秒上限，避免启动无限等待。
- Worker 在数据库认证阶段收到退出信号后，原逻辑仍会注册调度并输出 `worker-ready`。现每个异步启动阶段检查退出状态，关停后不再推进启动流程。
- 原错误脱敏包装将 BullMQ 限流信号变成普通失败，实际消耗重试次数。现保留延迟、等待与限流控制语义，业务异常仍使用固定失败码；回归验证延迟和限流恢复后仅计一次完成尝试。
- Redis 配置原先接受 `redis:///0` 等缺少主机的地址，现用 Zod 原生 `z.url` 限定协议与主机，同时删除重复 URL 解析。配置校验及重连策略的精简共减少 6 行，其余新增用于修复与回归验证。

本轮复核通过 ESLint、Prettier、33 项单元测试、10 项任务测试和差异空白检查。新增回归覆盖原 Queue 重连、Redis 不可用时命令超时退出、启动中退出和 BullMQ 控制信号；另验证缺少 `redis-server` 时现有测试清理能正常结束，无需修改。构建、53 项 MySQL API 集成及 8 条 Chromium 流程沿用上方本次基建实施阶段的通过记录；复核没有修改页面、API 或数据库结构。

## 当前实现边界

- 会话有效期 12 小时，数据库保存会话记录；退出后撤销对应记录。Cookie 使用 `HttpOnly`、`SameSite=Lax` 和显式的 `secure: false`。
- 双角色升级将 Cookie 名由 `admin_session` 改为 `starter_session`，旧浏览器需重新登录；账号密码不变。修改密码撤销全部会话。
- 登录限流为每个客户端 IP、每个进程 15 分钟内最多 10 次尝试。默认使用 socket IP；配置 `TRUSTED_PROXY_IPS` 后，仅可信代理的单值合法 `X-Forwarded-For` 用于区分客户端，代理须覆盖该头。多实例共享限流需后续另行设计。
- 公开注册独立使用相同的限流额度；关闭注册与注册事务通过设置行锁确定提交顺序。管理员创建用户不受注册开关影响。
- 管理员初始化不提供默认密码，重复运行不会重置已有管理员。修改环境变量中的初始密码不会修改数据库中的密码。
- MySQL 迁移包含自动提交的 DDL。发布前备份数据库，并由单个部署进程执行迁移。
- 当前 React 19 + Arco 组合通过公开的 `Message.useMessage()` 显示提示，弹窗使用受控组件；不依赖 Arco 的私有兼容补丁或全局样式覆盖。
