## 修复前来源错误的确定证据

用户 Chrome 的实际 Network 记录（未采集请求体或 Cookie）：

```text
页面 / 请求地址：http://127.0.0.1:3000/login → POST /api/auth/login
远程地址：127.0.0.1:3000
Host:    127.0.0.1:3000
Origin:  http://127.0.0.1
Referer: http://127.0.0.1:3000/login
Sec-Fetch-Site: same-origin
APP_ORIGIN: http://127.0.0.1:3000
响应：403 / INVALID_ORIGIN / 请求来源不被允许
X-Request-Id: a79487f2-3272-4869-8589-64a978ff5ac7
```

`src/server/api-handler.js:10` 精确比较 Origin。对非默认端口而言，缺少 `:3000` 即是不同来源；该请求在校验账号密码前已被拒绝。这是应用返回的 403，不是仅凭页面外观判断的浏览器 CORS 错误。

请求调用栈首层：

```text
window.fetch
chrome-extension://pgojnojmmhpofjgdmaebadhbocahppod/assets/aW5qZWN0X2hhc2g/aW5qZWN0X2hhc2g-a.js:11
→ 项目 request / login / onSubmit
```

这证明扩展参与了请求，不足以单独证明该扩展改写了 Origin。读取扩展管理页被浏览器策略拒绝，未绕过限制；具体扩展名称与改写规则尚未确认，未调整任何扩展设置。

## 修复前最小对照自测

向运行中的 `/api/auth/login` 发送 JSON 空对象，只改变 Origin，不创建会话或业务记录：

| Origin                  | HTTP / 错误码          | 结论                                 |
| ----------------------- | ---------------------- | ------------------------------------ |
| `http://127.0.0.1:3000` | `400 VALIDATION_ERROR` | 来源通过，随后因空表单被参数校验拒绝 |
| `http://127.0.0.1`      | `403 INVALID_ORIGIN`   | 复现 Chrome 中的缺端口拒绝           |
| `http://localhost:3000` | `403 INVALID_ORIGIN`   | 地址别名不是同一个 origin            |
| `null` / 缺失           | `403 INVALID_ORIGIN`   | 未绕过来源检查                       |

当时内置浏览器在相同页面使用一次刻意错误的测试密码，显示“用户名或密码错误”，能进入凭据校验；用户 Chrome 的实际提交仍显示“请求来源不被允许”。该次审计未验证正确密码登录，也未测试业务 CRUD。
